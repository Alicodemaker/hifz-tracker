# The Mushaf page can use the exact QCF4 fonts, downloaded once at runtime

The builder wants the Mushaf page to look like their reference app, which uses KFGQPC's QCF page fonts (glyph-per-word fonts where every printed line fills the width). Those fonts may not be redistributed without permission, so they are never stored in this repo or in the built app. Instead the app bundles only the MIT-licensed page data from the npm package `quran-qcf4@1.1.0` (which glyph goes on which line), and the phone downloads the 48 matching fonts (36 MB) once, on request, from jsDelivr's copy of that same pinned package. The fonts and the data must be the same version, or the page would show the wrong words. We rejected quran.com's font server because its font build uses different glyph codes.

This is a deliberate exception to "No runtime API calls" in AGENTS.md: a one-time, user-started download that is cached on the device, after which everything works offline. Until it finishes, or if it fails, the page falls back to the bundled KFGQPC Unicode text (ADR-0007), so a page is never blank. Supersedes the "no glyph fonts" part of ADR-0007.

**Update:** the download also takes the package's surah-name font (`QCF4_QBSML.woff2`, about 0.6 MB), which draws "سورة" and each surah's name as one calligraphic glyph in the surah banner. Phones that downloaded the page fonts before it was added fetch it once, quietly, the first time a banner shows; until then, and offline, the bundled font writes the name.
